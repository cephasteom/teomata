# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Teomata is a cellular automaton where custom rules can be added on the fly. The automaton's tick is driven by a musical clock (Tone.js), so steps happen in time with audio. It is an early-stage Svelte 5 + TypeScript + Vite single-page app (not SvelteKit).

## Commands

- `npm run dev`: start the Vite dev server
- `npm run build`: production build
- `npm run preview`: serve the production build
- `npm run check`: type-check (`svelte-check` for `src/` using `tsconfig.app.json`, plus `tsc` for the Vite/node config)

There is no test runner or linter set up yet. `npm run check` is the only verification step.

## Architecture

State lives in Svelte stores under `src/stores/`, and the components and the scheduler share them:

- `stores/global.ts`: app-wide settings (`isPlaying`, the fixed grid size `SIZE`, 64, and `zoom`, the squares per side the grid's window shows, default `DEFAULT_ZOOM` 16, `MIN_ZOOM` 4 to `MAX_ZOOM` 64) and the timing: `cps` (cycles, or bars, per second, default 0.5) and `q` (ticks per cycle, default 8), each with min and max constants, and `showConsole` and `showInstructions`, toggled by the controls' terminal and book buttons (dimmed while off), which hide the console (with the MIDI devices above it) and the instructions.
- Zoom and the window (`components/Grid.svelte`): the grid sits in a scrolling `.window` the size of `--grid-width` (in `app.css`), with its scrollbars hidden, showing `zoom` squares a side (App sets `--size` on the root to `zoom`, so `--square` and the text sizes follow it; the controls, console and instructions stay at `DEFAULT_ZOOM` through `.default-size`). The window scrolls as little as it takes to keep the cursor in view, and the open arguments as far as they fit. Cmd/Ctrl with `=`/`+`, `-`/`_` and `0` zoom in, out (through `levels`) and back to the default while the grid has focus, instead of the page; ctrl+wheel (a trackpad pinch) and Safari's gesture events zoom about the pointer; the wheel scrolls as usual. On touch (`touch-action: none`) one finger drags the grid and two pinch to zoom, a drag not clicking the square it ends on. `zoomTo` keeps the grid as still as it can under a point (the cursor's square when it's in view), with `flushSync` so the grid takes its new size before it scrolls. The view always lines up with the squares: `zoom` is a whole number of squares (the wheel adds up small turns in `wheelZoom`), zooming and following the cursor scroll by whole squares (`scrollToSquare`, with `pitch` measured between the first two squares, as the gridlines are fractions of a pixel), and after the wheel or a finger scrolls it, the window settles smoothly onto the nearest squares (`onscrollend`).
- `stores/cells.ts`: the grid. It is a **flat** `Cell[]` of length `SIZE²`, randomly seeded at module load (about 5% of cells get a random `value` and a random cardinal `direction`). A cell's `value` (type `Value` in `stores/cells.ts`) is a number, usually a whole MIDI value from 0 to 127 but not kept to it, so it can go negative or be fractional (`isValue` and `randomValue`, which seeds inside 0 to `MAX_VALUE`, in `lib/utils.ts`), a bang (type `Bang`, the string `'b'`, `BANG` in `lib/utils.ts`), or an array of numbers. A bang counts as a non zero value, and as a 1 wherever a number is needed (`toNumber` in `lib/utils.ts`). The grid shows a cell as a white square, inverting the label of any operation it passes over. An empty cell is `{}`. The rules step a module-level `grid`, which runs ahead of the `cells` store on screen by up to the scheduler's lookahead: `stepCells(tick)` reduces `grid` over the rule chain from `src/rules/` and returns it with the events the rules queued and a `version`, and `showCells(grid, version)` shows it unless the grid was changed since. `setCells(next)` replaces both at once and bumps `version`, so a grid stepped before it is dropped; `clearCells()` and `randomizeCells()` go through it.
- `stores/operations.ts`: one operation per square (`""` for none), typed at the cursor (only the letters in the `operations` table can be typed, checked with `kindOf`). Operations belong to the square, not the cell, so cells move over them. `args` holds each square's operation arguments as text (`string[]` per square), cleared when the square's operation changes. `muted` holds whether each square's operation is muted (`boolean[]`), toggled on the selection by Shift+Enter (`toggleMuted`, which mutes them all unless every one is already muted), cleared when the operation changes, and carried along with the operations and arguments by moving, copying, pasting and `persist.ts`. `applyRules` skips a muted square's rule but keeps it built, so it carries on from where it was, and `Grid.svelte` greys a muted square's label and border (`--cell-muted`), and its operation and arguments while they're open.
- `stores/editing.ts`: the argument editor. Enter on a square with an operation that has params opens it (`editing`), as does typing one, moving the cursor to the first argument; every other square hides apart from one square per param, in a row to the right of the operation (`argSquares`), with the operation shown moved left along its row (`shownSquare`) when they would run off the end. Typing replaces the argument under the cursor and then appends, left/right move between the arguments only, wrapping around at either end (clicking the operation's shown square does nothing), and Enter or Escape closes it, restoring the selection. An argument a param doesn't take as typed but whose arithmetic (`calculate` in `lib/arithmetic.ts`: `+ - * / % ^` and brackets) gives a number it does take, such as `1/8`, shows as valid and is replaced by the result, written by `formatArg` without a leading 0 (`.125`), when the cursor leaves it or the editor closes. With several squares selected, the editor opens on the cursor's square and each edited argument is also written to every selected square with the same operation. While it is open, `stepCells()` runs the edited squares on the operations and arguments they had before it opened (`holdOperations` and `appliedOperations` in `stores/operations.ts`), so a typed operation, or a change to its arguments, only takes effect once the editor closes.
- `stores/history.ts`: undo and redo for the operations, arguments and mutes, keeping the last `HISTORY` (4) changes. Each change in `Grid.svelte` goes through `change(make)` (or `snapshot()` then `record(before)`), which keeps a snapshot from before it, with the cursor and anchor, unless nothing changed (compared square by square), and drops anything that could be redone. An argument editing session is one change: `openArgs` keeps the snapshot it is given and `closeArgs` records it. Cmd/Ctrl+Z undoes, and Cmd/Ctrl+Shift+Z or Cmd/Ctrl+Y redoes, while the grid has focus and no arguments are open. Undoing restores the selection from before the change.
- `stores/console.ts`: the lines printed by the `p` operation (`formatValue`, an array as its numbers joined by commas, through `printLine`, called by the scheduler for its `print` events), keeping the last 500, emptied by `clearConsole` (the controls' Clear button, along with the cells but not the operations, and `toggle()` each time it starts the transport). `components/Console.svelte`, under the controls and `Devices` to the grid's left (the two share a column in `App.svelte`, a square apart, the console taking the height left), lists them one per line, aligned right to line up with the controls, with its own monochrome scrollbar (the browser's hidden) drawn in the gap before the grid, shown while it's scrolled by hand (wheel, touch or keys), hovered or dragged and fading out a second after, but not when it scrolls to follow new lines, and, like a terminal, follows new lines while scrolled to the bottom.
- `lib/midi.ts`: enables WebMidi (the `webmidi` package) at import time and keeps the `inputs` and `outputs` stores up to date as devices connect and disconnect. `components/Devices.svelte` lists the outputs, each by its index, under the heading "MIDI devices:". `playNote(device, channel, notes, amp, dur, at?)` plays, and `sendControl(device, channel, controller, value, at?)` sends a control change, on the output at that index at the MIDI time `at` (now when it's left out or past), doing nothing when there isn't one. `midiTime(time)` turns a time on Tone's audio clock into one on WebMidi's (`WebMidi.time + (time - immediate()) * 1000`).
- `stores/persist.ts`: imported by `main.ts` before the app mounts. It restores `cps`, `q`, `zoom`, `showConsole` and `showInstructions`, `operations`, `args` and `muted` from `localStorage` (keys prefixed `teomata:`), skipping any saved value that is out of range or doesn't fit the grid, then saves each store whenever it changes. Operations saved when the grid could be resized (with its size under `s`) are copied onto the grid's top left with `resize` from `lib/utils.ts`, and `s` is removed.
### Rules (`src/rules/`)

`rules.md` at the repo root is the specification of every operation (its signature, defaults and how it displays); keep it and the code in step. The rules live in their own files (`move.ts`, `bang.ts`, `count.ts`, `value.ts`, `die.ts`, `harmony.ts`, `math.ts`, `logic.ts`, `print.ts`, `rotate.ts`, `scale.ts`, `wave.ts`, `note.ts`, `cc.ts`), with a generator and the operator sharing its name in one file (`bang.ts`, `value.ts`, `wave.ts`). The shared types (`GridRule`, `CellRule`, `Kind`, `Param`, `Operation`) are in `rules/types.ts`, and `rules/shared.ts` holds what several rules use: `isNumber` and `isWhole` checks, param builders (`directionParam`, `cyclesParam`, `deviceParam`, `channelParam`), `fires(cycles, tick)` for a generator's schedule (the first tick at or after every `cycles × q` ticks) and `isMoving` (a cell with a direction and a value, the only cells operators and outputs act on). Every operation's and param's `about` text lives in `rules/instructions.ts` (the `about` table, keyed by letter, as a generator and an operator share a name, with each param's text under `params` by its name), so it can be edited as a whole, and is shown as HTML, so it can hold links. `rules/index.ts` wires them together: the `operations` table, `applyRules`, `paramsFor`, `argsFor`, `kindOf`, `labelFor`, `instructions` (every operation by letter, generators, then operators, then outputs, each alphabetically, listed by `components/Instructions.svelte` to the grid's right with each letter coloured by its kind, showing only the operation under the cursor, or the one being edited, when there is one and the grid has focus), and the exported `rules` chain. The chain is a plain array, not a store.

- A `GridRule` is a `(cells, size, operations, args, muted, tick) => Cell[]` function over the whole grid. `rules` is `[move, applyRules]`, and `stepCells()` reduces over it each tick.
- `move` steps each cell in its direction. A cell that would step past the edge of the grid dies. Cells that would hit each other bounce off, and cells landing on the same square overwrite each other.
- `applyRules` is a single pass that looks up each square's operation in the `operations` table. **Case matters**: generators are uppercase and may share a letter with a lowercase operator. An `Operation` has a `name` (shown in the instructions with its params in brackets, `print()` for none), a `kind` (`generator`, `operator` or `output`), `about` text (shown under it when it is the only operation shown, with each param's `about`), `params` (each with a `name`, `about` text, a text `fallback` and an `accepts` check), an optional `rest` param that repeats after them to fill the rest of the row (`paramsFor(letter, size)` gives `size - 1` params in all; no operation uses it at the moment), an optional `shown` count of the params the editor shows for the arguments given, an optional `label` built from its arguments, and a `rule` that builds a per-square `CellRule` `(cell, tick) => Cell` from its arguments. `applyRules` keeps each square's built rule from tick to tick until its operation or arguments change, and builds them all afresh on tick 0, so a rule can keep state in its closure (as `i` keeps its count). Any missing or invalid argument uses its fallback. The cell is `{}` on an empty square.
- Display: `Grid.svelte` shows each square's `labelFor(i, letter, size, args)` instead of its letter (the letter shows while its arguments are open): the built rule's own `label()` when it has one (none has at the moment), else the operation's `label(...args)`, else the letter, worked out again each time the cells change, shrinking to fit the square. Labels show in bold, apart from a label that is a lone arrow (`r`'s), which shows bigger and not bold. Generators are bordered in `--cell-generator` (green) and outputs in `--cell-output` (blue), through `borders` in `Grid.svelte` by `kindOf`, hidden while an operation's arguments are open.
- Directions: a `direction` param (`directionParam`) takes `n`, `e`, `s`, `w`, or `x`, `y` or `xy` for a random direction along that axis or either, or its number from 0 to 6 in that order, kept as its name when the cursor leaves it (the param's `settle`, which `settled` in `stores/editing.ts` applies, as `W`'s and `w`'s `type` does for its number) (type `heading`, with `headingOf` to read one as typed, `isHeading`, `pickDirection` and the `arrows` it shows as, `↑ → ↓ ← ↔ ↕ ⤡`, in `lib/utils.ts`), picked afresh for each cell.
- Generators put a new cell on their square every `n` cycles (`cyclesParam`, default 1, any number above 0, so .5 is twice a cycle) heading in their `direction` (default `e`) for `move` to carry off; cells arriving between times pass through. Generators show as their capital letter, apart from `V`. `B` is `bang(n, direction)`. `V` is `value(value, n, direction)` (`value` any number, default 0), shown as its value. `W` is `wave(freq, type, n, direction)` (`freq`, any number, default 1, the waveform's cycles per bar, and `type` `saw`, `sin`, `cos`, `tri`, `sqr` or `noi`, ignoring case, or its index in that list from 0, default `sin`), which puts out the waveform's value, from 0 to 1, at the tick (its phase is `tick / q × freq`, so it is in step with the transport from its start). `noi` is value noise: a seeded hash gives a random value at each whole phase, smoothstepped into the next, seeded afresh each time the rule is built, so each square and each run differs.
- Operators act on moving cells with a value, keeping their direction, except `d` (`die`), which removes whatever cell is on the square. `b` is `bang`, which turns the value into a bang. `i` is `increment(from, to)` (`from` default 0 and `to` default 7, any numbers, in `count.ts`), which gives each value that arrives the next count, stepping by 1 towards `to` (down when `to` is below `from`) and wrapping back to `from` once it would pass `to`, shown as `i`. `v` is `value(value)`, which gives each value that arrives the value (default 0), shown as it. `createValues` in `value.ts` (the spec's `values()`) gives a single value as it is, or, given several, the array of them to a bang or an array, and to a number the value at its index, rounded and wrapped to the array's length. `h` is `harmony(root, type, octaves)` (`root` a note from `a` to `g` with an optional `#` or `b`, default `c`, `type` a two letter chord or a three letter scale or mode alias from `harmonies` in `lib/harmony.ts`, default `ma`, both ignoring case, and `octaves` 1 to 8, default 1), which works through `createValues` over the harmony's MIDI notes, its root in the octave from middle C (60), repeated in each octave above, shown as the root in capitals and the type, cut to 3 letters, such as `Cma` or `F#d`. `m` is `math(operator, n)` (`operator` ignoring case, default `+`, and `n`, any number, default empty, shown in the editor only for the operators that take it), which changes the value (a bang counting as 1), or each number of an array value, without rounding, by an operator after the JS Math object (the `operators` table in `math.ts`): `+`, `-`, `*`, `/`, `%`, `^` (or `pow`), `&` and `|` (bitwise, on whole numbers), `atan2`, `min`, `max` and `hypot` take the value and `n` (leaving the value alone when it is empty), and the rest of Math's one-number functions (`abs`, `round`, `sqrt`, `log`, `sin` and so on) take the value alone, as does `~` (bitwise not). A number whose result isn't finite, such as after dividing by 0, is left as it was. `l` is `logic(operator, n)` (`operator` default `==`, and `n`, any number, default 0, shown in the editor only for the operators that take it), which turns the value into a bang if it passes a test by an operator after JS's own (the `operators` table in `logic.ts`), and removes the cell if not: `<`, `>`, `<=`, `>=`, `==` (or `===`), `!=` (or `!==`), `&&`, `||` and `^` (xor) test the value against `n`, and `!` (not) tests the value alone, a number being true when it isn't 0. A bang counts as 1, and an array value passes only when every one of its numbers does. `m` and `l` show as their operator. `p` is `print()`, which prints the value to the console. `r` is `rotate(direction)` (default `x`), which turns the cell to the direction, shown as its arrow. `s` is `scale(lo, hi, inLo, inHi)` (any numbers, defaults 0, 127, 0 and 1), which maps the value (a bang counting as 1), or each number of an array value, linearly from `inLo` to `inHi` onto `lo` to `hi`, without clamping, leaving it as it was when the result isn't finite (`inLo` equal to `inHi`). `w` is `wave(freq, type)`, which gives each bang or non zero value that arrives the waveform's value at the tick, as `W` does, leaving 0 alone, shown as its type.
- Outputs (`note.ts`, `cc.ts`) take `device` (an output's index in `outputs` from 0, default 0) and `channel` (1 to 16, default 1), ignore bangs, leave the cell alone, round each number and wrap it into 0 to 127 (`toMidi`). Rules don't send or print anything themselves: `n`, `c` and `p` queue events with `emit` from `rules/events.ts` (`note`, `cc` and `print`), which `stepCells` drains for the scheduler. `n` is `note(vel, dur, device, channel)` (`vel` 0 to 127, default 100, and `dur` in seconds, above 0, default .5), which plays a number as a MIDI note, or an array as a chord, at the velocity for `dur` seconds. `c` is `cc(cc, device, channel)` (`cc` 0 to 127, default 1), which sends a number as a control change, or the first number of an array, shown as `cc` and its controller, such as `cc7`.
- To add an operation, write it in its own file exporting an `Operation` (with `params: []` for one without params, and its `kind`), add its `about` text to `rules/instructions.ts` under its letter, add an entry to `operations` in `rules/index.ts` and add it to `rules.md`. Rules that need the whole grid go in the `rules` chain as full `GridRule`s.

Shared direction helpers (`step` for a one-square move, undefined past the edge, which also stops the cursor there, `resize` for copying saved operations onto the grid's size, `opposite`, `isDirection`, `randomDirection`, and `heading`, `isHeading`, `pickDirection` and `arrows` for the directions operations are given) live in `src/lib/utils.ts`. `src/lib/harmony.ts` holds the chords and scales as semitones above the root, with `harmonies` mapping each chord (two letters) and each scale and mode alias (three letters) to its notes; full scale names are not accepted.

`src/scheduler.ts` owns timing. At import time it creates a Tone.js `Loop` firing `q` times a bar (`"${q}n"`, updated when `q` changes), keeps the transport's tempo at `cps` (`cps × 4 × 60` BPM), and works out each tick from the transport's position, so it starts from 0 when the transport starts and stays on the bar's divisions when `q` changes. `toggle()` starts or stops the Tone transport, clearing the console on start, and flips `isPlaying`. Tone fires the loop's callback ahead of the audio clock (its lookahead), so each tick calls `stepCells(tick)` there and then, sends its `note` and `cc` events through `playNote` and `sendControl` at `midiTime(time)`, so MIDI lands exactly on the tick, and uses `getDraw().schedule` to show the grid and print its `print` events when the tick is heard. Space calls `toggle()` from anywhere (the window's keydown in `Grid.svelte`), except while an operation's arguments are open, where it does nothing. `toggle()` calls Tone's `start()` first because the audio context needs a user gesture.

Stores are read outside components with `get(store)` from `svelte/store`. Components use the `$store` auto-subscription syntax together with Svelte 5 event attributes (`onclick={...}`).
