# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Teomata is a cellular automaton where custom rules can be added on the fly. The automaton's tick is driven by a musical clock (Tone.js), so steps happen in time with audio. It is an early-stage Svelte 5 + TypeScript + Vite single-page app (not SvelteKit).

## Commands

- `npm run dev`: start the Vite dev server
- `npm run build`: production build
- `npm run preview`: serve the production build
- `npm run check`: type-check (`svelte-check` for `src/` using `tsconfig.app.json`, plus `tsc` for the Vite/node config)

There is no test runner or linter set up yet. `npm run check` is the only verification step.

## Architecture

State lives in Svelte stores under `src/stores/`, and the components and the scheduler share them:

- `stores/global.ts`: app-wide settings (`isPlaying`, `gridSize`) and the timing: `cps` (cycles, or bars, per second, default 0.5) and `q` (ticks per cycle, default 8), each with min and max constants. `gridSize` (default 16, `MIN_SIZE` 4 to `MAX_SIZE` 64) is only changed through `resizeGrid`.
- `stores/size.ts`: `resizeGrid(size)` closes the argument editor, resizes `cells`, `operations` and `args` with `resize` from `lib/utils.ts` (growing adds empty squares right and bottom, shrinking truncates them, and every square that stays keeps its state), keeps the cursor and anchor on their squares or clamps them to the new edge, then sets `gridSize`. `size` wraps `gridSize` as a `Writable` whose `set` resizes, for the controls' `s` square.
- `stores/cells.ts`: the grid. It is a **flat** `Cell[]` of length `gridSize²`, randomly seeded at module load (about 5% of cells get a random `value` and a random cardinal `direction`). A cell's `value` (type `Value` in `stores/cells.ts`) is a number, usually a whole MIDI value from 0 to 127 but not kept to it, so it can go negative or be fractional (`isValue` and `randomValue`, which seeds inside 0 to `MAX_VALUE`, in `lib/utils.ts`), a bang (type `Bang`, the string `'b'`, `BANG` in `lib/utils.ts`), or an array of numbers. A bang counts as a non zero value, and as a 1 wherever a number is needed (`toNumber` in `lib/utils.ts`). The grid shows a cell as a white square, inverting the letter of any operation it passes over. An empty cell is `{}`. `updateCells()` reduces the grid over the rule chain from `src/rules/`; `clearCells()` and `randomizeCells()` empty or reseed it.
- `stores/operations.ts`: one operation per square (`""` for none), typed at the cursor (a letter). Operations belong to the square, not the cell, so cells move over them. `args` holds each square's operation arguments as text (`string[]` per square), cleared when the square's operation changes.
- `stores/editing.ts`: the argument editor. Enter on a square with an operation opens it (`editing`), as does typing an operation with params, moving the cursor to the first argument when there is one; every other square hides apart from one square per param, in a row to the right of the operation (`argSquares`), with the operation shown moved left along its row (`shownSquare`) when they would run off the end. Typing replaces the argument under the cursor and then appends, left/right move between the arguments only, wrapping around at either end (clicking the operation's shown square does nothing), and Enter or Escape closes it, restoring the selection. With several squares selected, the editor opens on the cursor's square and each edited argument is also written to every selected square with the same operation. While it is open, `updateCells()` runs the edited squares on the operations and arguments they had before it opened (`holdOperations` and `appliedOperations` in `stores/operations.ts`), so a typed operation, or a change to its arguments, only takes effect once the editor closes.
- `stores/console.ts`: the lines printed by the `p` operation (`printValue`, an array as its numbers joined by commas) and the `o` operation (`printLine`, which takes an optional colour for the line), keeping the last 500, emptied by `clearConsole` (the controls' Clear button, along with the cells and operations). `components/Console.svelte`, under the controls and `Devices` to the grid's left (the two share a column in `App.svelte`, a square apart, the console taking the height left), lists them one per line, aligned right to line up with the controls, with its own monochrome scrollbar (the browser's hidden) drawn in the gap before the grid, and, like a terminal, follows new lines while scrolled to the bottom.
- `lib/midi.ts`: enables WebMidi (the `webmidi` package) at import time and keeps the `inputs` and `outputs` stores up to date as devices connect and disconnect. `components/Devices.svelte` lists the outputs, each by its index, under the heading "MIDI devices:". `playNote(device, channel, notes, amp, dur)` plays on the output at that index, doing nothing when there isn't one.
- `stores/persist.ts`: imported by `main.ts` before the app mounts. It restores `cps`, `q`, the grid size (`s`, through `resizeGrid`), `operations` and `args` from `localStorage` (keys prefixed `teomata:`), skipping any saved value that is out of range or doesn't fit the grid, then saves each store whenever it changes.
### Rules (`src/rules/`)

Each rule lives in its own file (`move.ts`, `rotate.ts`, `die.ts`, `bang.ts`, `values.ts`, `harmony.ts`, `counter.ts`, `explode.ts`, `math.ts`, `logic.ts`, `print.ts`, `out.ts`). The shared types (`GridRule`, `CellRule`, `Param`, `Operation`) are in `rules/types.ts`. Every operation's and param's `about` text lives in `rules/instructions.ts` (the `about` table, keyed by operation name, with each param's text under `params` by its name), so it can be edited as a whole, and is shown as HTML, so it can hold links; each rule file reads its text from there. `rules/index.ts` wires them together: the `operations` table, `applyRules`, `paramsFor`, `argsFor`, `instructions` (every operation by letter, the symbols first and then the letters alphabetically, listed by `components/Instructions.svelte` to the grid's right, showing only the operation under the cursor, or the one being edited, when there is one and the grid has focus), and the exported `rules` chain. The chain is a plain array, not a store.

- A `GridRule` is a `(cells, size, operations, args, tick) => Cell[]` function over the whole grid. `rules` is `[move, explodeArrays, applyRules]`, and `updateCells()` reduces over it each tick.
- `move` steps each cell in its direction, wrapping around the edges. Cells that would hit each other bounce off, and cells landing on the same square overwrite each other.
- `explodeArrays` (in `explode.ts`) explodes the array value of the cell on every `x` square out in a line in its `direction` argument: the first number stays on the square and each one after goes one square further, wrapping around the edges, as a cell with the original's direction, overwriting whatever cell is there. For `x` or `y` the numbers after the first take turns going either way along that axis (east then west, or north then south), each one square further than the last that went the same way. Cells are read before any explosions, and single values are left alone.
- `applyRules` is a single pass that looks up each square's operation (case-insensitive) in the `operations` table. An `Operation` has a `name` (shown in the instructions), `about` text (shown under it when it is the only operation shown, with each param's `about`), `params` (each with a `name`, `about` text, a text `fallback` and an `accepts` check), an optional `rest` param that repeats after them to fill the rest of the row (`paramsFor(letter, size)` gives `size - 1` params in all, so its editor opens the whole row with the operation in the first square) and a `rule` that builds a per-square `CellRule` `(cell, tick) => Cell` from its arguments. `applyRules` keeps each square's built rule from tick to tick until its operation or arguments change, and builds them all afresh on tick 0 or a resize, so a rule can keep state in its closure (as `counter` keeps its count). Any missing or invalid argument uses its fallback. The cell is `{}` on an empty square.
- Operations: `r` is `rotate` (param `direction`, default `x`), which turns a moving cell to face `n`, `s`, `e` or `w`, or for `x` or `y` reverses a cell travelling along that axis and sends the cells travelling across it either way along it, taking turns (east then west, or north then south), and `d` (`die`) removes whatever cell is on the square. `b` is `bang` (params `bars`, default 1, and `direction`, default east, its square bordered in `--cell-bang`, through `borders` in `Grid.svelte`, like `o`'s in `--cell-out`), which puts a new cell with a bang value heading that way on the square every `bars` bars for `move` to carry off, or for `x` or `y` heading either way along that axis, taking turns (east then west, or north then south). `v` is `values` (rest param `value`, any numbers, not just whole ones, with empty ones skipped), which keeps a moving cell's direction and, given a single value, gives the cell that value, or given more, gives it the array of them when its value is a bang or an array, or the value at the index of a number value, rounded and wrapped to the array's length, leaving the cell alone when given none. `h` is `harmony` (params `type`, a two letter chord or a three letter scale or mode alias from `harmonies` in `lib/harmony.ts`, default `ma`, and `root`, a note from `a` to `g` with an optional `#` or `b`, default `c`, both ignoring case), which works like `values` (through `createValues` in `values.ts`) over the harmony's MIDI notes, its root in the octave from middle C (60). `c` is `counter` (params `from`, default 0, and `to`, default 7, any numbers), which keeps a count starting at `from`, giving each moving cell with a value that arrives the count and then stepping it by 1 towards `to` (down when `to` is below `from`), wrapping back to `from` once it would pass `to`. `x` is `explode` (param `direction`, `n`, `s`, `e`, `w`, `x` or `y`, default north), whose own rule leaves the cell alone, the exploding being done by `explodeArrays`. `m` is `math` (params `operator`, ignoring case, default `+`, and `n`, any number, default empty, shown in the editor only for the operators that take it, through the `Operation`'s optional `shown` count, which `paramsFor` applies when given the arguments), which changes a moving cell's value (a bang counting as 1), or each number of an array value, without rounding, by an operator after the JS Math object (the `operators` table in `math.ts`): `+`, `-`, `*`, `/`, `%`, `^` (or `pow`), `&` and `|` (bitwise, on whole numbers), `atan2`, `min`, `max` and `hypot` take the value and `n` (leaving the value alone when it is empty), and the rest of Math's one-number functions (`abs`, `round`, `sqrt`, `log`, `sin` and so on) take the value alone, as does `~` (bitwise not). A number whose result isn't finite, such as after dividing by 0, is left as it was. `l` is `logic` (params `operator`, default `==`, and `n`, any number, default 0, shown in the editor only for the operators that take it), which turns a moving cell's value into a bang if it passes a test by an operator after JS's own (the `operators` table in `logic.ts`), and removes the cell if not: `<`, `>`, `<=`, `>=`, `==` (or `===`), `!=` (or `!==`), `&&`, `||` and `^` (xor) test the value against `n`, and `!` (not) tests the value alone, a number being true when it isn't 0. A bang counts as 1, and an array value passes only when every one of its numbers does. `p` is `print` (no params), which prints the value of each moving cell that arrives to the console, leaving the cell alone. `o` is `out` (params `device`, an output's index in `outputs` from 0, default 0, and `channel`, 1 to 16, default 1), which plays each moving cell with a number that arrives as a MIDI note, or an array as a chord, rounded and kept to 0 to 127, at a fixed velocity (100) and length (0.5 seconds) through `playNote`, and prints the notes to the console in `--cell-out`, the colour of the border the grid draws round its square (hidden while an operation's arguments are open). Bangs are ignored, and the cell is left alone.
- To add an operation, write it in its own file exporting an `Operation` (with `params: []` for one without params), add its `about` text to `rules/instructions.ts` and add an entry to `operations` in `rules/index.ts`. Rules that need the whole grid go in the `rules` chain as full `GridRule`s.

Shared direction helpers (`step` for a wrapping one-square move, `resize` for copying a grid onto a new size, `opposite`, `isDirection`, `randomDirection`, and `axes` and `isAxis` for the `x` and `y` axes, each as its two directions in turn) live in `src/lib/utils.ts`. `src/lib/harmony.ts` holds the chords and scales as semitones above the root, with `harmonies` mapping each chord (two letters) and each scale and mode alias (three letters) to its notes; full scale names are not accepted.

`src/scheduler.ts` owns timing. At import time it creates a Tone.js `Loop` firing `q` times a bar (`"${q}n"`, updated when `q` changes), keeps the transport's tempo at `cps` (`cps × 4 × 60` BPM), and works out each tick from the transport's position, so it starts from 0 when the transport starts and stays on the bar's divisions when `q` changes. `toggle()` starts or stops the Tone transport and flips `isPlaying`. Each loop tick calls `updateCells(tick)` via `getDraw().schedule` so the visual update lands on the audible tick. `toggle()` calls Tone's `start()` first because the audio context needs a user gesture.

Stores are read outside components with `get(store)` from `svelte/store`. Components use the `$store` auto-subscription syntax together with Svelte 5 event attributes (`onclick={...}`).
